## 实现范围

P3 复用原高德 v5 客户端，新增确定性 POI 规范化、三态匹配、可解释排序、POI 覆盖与缓存、地点/地图/起点业务 API，以及 React 候选地图。未新增依赖。P0 搜索默认 5 条并返回原始响应的行为保留；P0 独立地图继续通过 `/p0/map` 访问，不替代正式工作区验收。

| 项目 | 当前实现与限制 |
|---|---|
| POI 字段 | 只规范化真实高德 ID、GCJ-02 坐标及返回字段；保存读取时间、v5 版本和字段缺失列表，缺入口不使用中心点替代 |
| 消歧 | `unique/ambiguous/unmatched` 及备选列表；完整可取得分页、同城同类别、原名或分店明确才自动接受，简称、泛称、方向、缺字段和多分店不猜首项 |
| 人工确认 | 只选择已存备选，并再次调用该 ID 的高德详情核对名称、ID、坐标及城市；失败保留原匹配 |
| 有界请求 | 每次核对最多 20 个候选、40 次物理请求、60 秒；名称查询至多两页、每页 20 条，未穷尽则保持歧义；应用内共享 1.1 秒请求间隔，无自动 QPS 重试 |
| 缓存 | 名称、城市、接口版本作键，TTL 24 小时；保留原读取时间，缓存命中不新增物理请求，仅存脱敏标准 POI 字段 |
| 排序 | 已核城市/类别资格、明示短语的关联原文字面命中、不同作者、亲历正负证据、原发布时间；理由保留引用 IDs，未知偏好不臆测，负面或混合命中提示冲突 |
| 费用与状态 | 当前营业、价格、预约和政策未取得时保持未知；历史价格不作当前预算硬约束，发布时间不代表当前有效，不构造全平台好评率 |
| 地图集合 | 首次前 8 个不同 POI，起点另计；同 ID 别名共用点但原候选、来源、活动和证据分开保留，客户端只绘制已展示 ID 集合 |
| 后续操作 | 增量加点与行程选择分别保存；后续匹配不自动替换地图，显式确认刷新才重取整组，视野和城市图层可恢复 |
| 出发点 | 文字不推测坐标；可搜索高德地点后确认或由用户地图点选确认，改变出发地文字会清除旧坐标确认 |
| 版本与归属 | 查询及更新按行程归属；异步提交复查条件、匹配会话及工作区版本，晚到结果不能替换较新的地图或人工确认 |

SQLite 连续迁移 [004_places.sql](../backend/easytrip/storage/migrations/004_places.sql) 将 `PRAGMA user_version` 升为 4，新增 `place_match_sessions/candidate_matches/poi_search_cache/origin_searches`。POI 覆盖独立于原 P2 候选和来源，不重建数据库，不替换用户行程。业务契约详见 [API README](../backend/easytrip/api/README.md#p3-地点地图与出发点)。
