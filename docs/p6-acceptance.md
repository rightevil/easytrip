## 第一步验收：安全与确定性回归

修复三项可复现缺口：未知 `api_key/access_token/password/cookies` 等字段与复合值未完全脱敏；MCP 服务 schema 的外部引用可以绕开固定网络目标；第三方 SDK 警告/异常可能包含原始响应与凭证 URL。

统一参数校验拒绝外部 HTTP/file/相对引用，使用不检索资源的 Registry；本地 `$defs`、动态/递归锚点仍可校验，非法递归安全停止。XHS、采集和铁路使用同一入口，参数/服务 schema 错误不会启用写工具或追加外部下载。第三方 transport 日志只保留模块、级别与异常类，调用详情由受控台账记录。

新增实际应用回归覆盖恶意来源/schema 不能修改模型目标、预算或增加购票/写工具，陌生 Host/Origin 不能创建数据，模型鉴权失败的正文/凭证不进入任务 API；构造响应全部为脱敏测试数据，无真实调用。

验证命令：`uv --directory backend run pytest -q`，990 项通过（142.64 秒）；`uv --directory backend run ruff check .` 与 8 个改动 Python 文件格式检查通过。前端代码未变，保留上一切片 150 项和构建证据。本步没有把 T05 真实语义失败、T07 人工未认证或后续真实验收标成通过。数据库 schema 与依赖未改变。

## 第二步验收：Windows 启动与数据恢复

Windows 入口增加 `check/backup/restore`。启动前检查构建、端口、依赖与数据库，只监听本机单 worker；端口占用不会结束原进程。外部配置仅显示完整性，不输出值或探测服务，离线草稿可独立启动；预构建后不要求 Node/npm。

SQLite 维护工具使用只读源连接和 backup API，保留已提交 WAL，输出独立的 DELETE journal 备份。检查完整性、外键、受支持的 schema 与表/列，不迁移源库；拒绝损坏/普通/未来版本、已有目标及同名侧文件。迁移前自动备份，备份失败则不修改版本或 journal mode；迁移失败仍保留原版本备份。

专项 130 项回归通过，包括 41 项维护测试、Windows 端口/参数保护、诊断脱敏及既有迁移；另加入迁移失败后备份可恢复的回归。最终完整后端 **1039 项通过（187.46 秒）**，Ruff 与 5 个新增 Python 文件格式检查通过。仍只有既有 Starlette/httpx 弃用警告；前端本步无改动。

实际恢复演练在 `reports/p6/recovery-409e4c28/proof.json`：通过真实 PowerShell 入口，备份/恢复历史 P4 验收库，schema 7→8 自动升级后用当前应用重开 2 个行程；2 条消息、327 条来源、1769 条来源快照、73 个候选、2 个匹配及 7 个方案的原有列/内容指纹一致，已采用方案 ID 保留。原 QA 库和正式库未改动，外部请求为 0。另有临时构造用例证明未完成任务恢复为 `recoverable`，不自动重放。

操作说明见 [Windows 运行与数据恢复](windows-operations.md)。本步未演练物理磁盘写满，也未替换正式用户数据库；不能据此宣称所有真实端到端场景完成。

## 第三步验收：用量与费用核对

schema 9 增加独立的同步查询账本，按行程和条件版本记录 P3 匹配、手动候选、起点及确认的每次高德物理请求，铁路按站名/余票两只读工具分别计量；不伪造发现任务，不占用或串入无关 Run 的预算。每次发送前必须成功记账，记账失败停止后续请求。取消/重启未结清保留未知，不自动重放；晚到业务结果遭 409 拒绝仍保留原行程的调用记录。缓存单独记命中且不增加外部调用。

`GET /api/trips/{id}/usage` 返回本应用已记录的 Run/API/provider 分项、token/图片、缓存、失败/未知/在途及耗时；明确账号总费用未知、单价未核定。按只读事务构造一致快照，权威 Run 累计与动作分类分开，避免重复累加。导出仅含白名单元数据和版本/指纹，排除请求参数、原始服务结果、帖子及密钥，再以当前配置脱敏。旧模型 ID、旧调用耗时和首次候选时间缺失保持未知。新候选首次发布时间与候选在同一事务写入，只记录一次；模型 ID 按实际物理请求冻结。

界面新增按需“读取最新用量”，没有发现任务也可查看同步查询记录；读取失败不显示零，切换行程丢弃旧响应。报告不是整账号账单；历史同步查询、高德 JS/底图、协议握手及用户维护服务资源不在业务调用完整统计范围。人民币始终 `null`，不套用未经核实的单价。

历史真实台账副本核对记录 `reports/p6/usage-bd11bb74/proof.json`：两个隔离行程中，一条为 78 次已记录调用、561308 个已知模型 token、9 次图片提交、4 次模型用量不完整，provider 分项与 SQLite 累计一致；另一条无已记录调用。该核对产生 0 次外部请求，没有新增模型消费或改动正式库，不能把历史小计当成本次消费。新同步查询的准确计数由临时库/脱敏响应回归验证，真实新链路留到第四步。

针对性工程验证已覆盖成本隔离、幂等、缓存、失败阻断、晚到计费、未知恢复、schema 9 迁移及首候选记录；最终完整后端 **1088 项通过（128.18 秒）**，153 项前端回归、生产构建和 Ruff 通过。仍只有既有 Starlette/httpx 弃用警告；没有新增依赖。真实服务新链路尚未因此获得验收通过。
