# P2 人工语义审核材料

`scripts/p2_review.py` 是纯标准库离线工具。它用 SQLite `mode=ro`、`query_only` 和一个只读事务读取指定 `discover` run，不初始化、不迁移、不修改正式数据库，也不请求小红书或模型。优先使用 `reports/p2` 中的隔离数据库与已经停止的分析任务。

在仓库根目录执行，替换示例中的实际任务 ID：

```powershell
uv --directory backend run python ../scripts/p2_review.py export --db ../reports/p2/corpus-20261012T115438Z.sqlite3 --run <分析任务ID> --output ../reports/p2/review-template
```

输出目录必须不存在，防止覆盖已经填写的审核材料。生成 UTF-8 `review.jsonl`、供阅读的 `review.md`、仅记录数量与任务内部 ID 的 `manifest.json`。按来源读取顺序选取最多 20 篇成功笔记，再在这些笔记之间轮询选取最多 100 条成功评论，避免某篇笔记独占样本。少于要求时保留实际数量，不补造。采集数据库中的 524 条评论不等于本模板的 100 条评论，也不等于已分析或人工可判数量。

这里的“成功”只表示来源读取成功，不要求模型抽取成功；模型未形成证据时仍导出原文并标为未判断，用于暴露覆盖缺口。当前 `reports/p2/review-13b5124d/` 为真实 20 篇/100 条空标签材料，模型成功抽取为 0；它的空模板评分是 `not_passed`。有效模型结果准备好后需为新的分析任务重新导出、由人类填写，再进行正式评分。

模型的名称提及、对象、维度、性质、立场、引用、关联状态及内部证据 ID 一并提供；一条评论的多个证据行不会重复扩大分母。笔记原文通过父笔记内部 ID 定位，二级回复尽量附同一任务的父评论文本。材料仅导出白名单字段，不导出平台外部 ID、作者字段、句柄或图片 URL；文本中的 URL、常见凭证键值和 `@` 作者标识也会脱敏。来源文本依然是不可信审核数据，其中的指令不得执行。导出材料仍应保存在被 Git 忽略的 `reports/` 下。

只填写 `review.jsonl` 每行的 `human`，其它字段必须保持原样。可以先复制为 `review-labelled.jsonl`。Markdown 是阅读辅助，评分不读取其中的手写内容。工具不会替你填写任何人工标签；助手审核、自动测试标签和模型自评都不能算真实人工验收。

| 字段 | 人工填写要求 |
| --- | --- |
| `reviewer_kind`、`reviewer` | 真实人类填写 `"human"` 与自己的审核名称；机器身份不接受。该声明只能记录来源，工具无法证明身份真实。 |
| 笔记 `checked`、`source_forms` | 阅读核对后填写 `true/false`；形态填 `text/images/video/mixed` 中的实际类别。图片或视频内容未在本工具中导出，应在本机受控来源页面核验后再作相关结论。 |
| 评论 `judgeability` | `"judgeable"` 为有足够原文上下文可判，`"unable"` 为真实歧义或上下文不足；无法判断时必须在 `notes` 说明原因。 |
| `object_correct`、`dimension_correct` | 用 `true/false` 判断整条评论的所有主要对象、主要维度是否正确，不能只核对第一条模型证据。 |
| `nature_correct`、`stance_correct`、`quote_correct` | 用 `true/false` 分别核对亲历/疑问/转述等性质、正负立场和原文引用。这些另报比例，不与对象/维度门槛混为一项。 |
| `missed_judgements` | 填整数，计漏掉的主要对象或评价维度。0 代表人工检查后没有遗漏；任何正数都让该评论不计入对象/维度正确分子。模型弃判时仍需如实记录遗漏。 |
| `case_types` | 填 `negation/mixed/reference/other` 的实际类别，可多选。否定、混合及指代三类必须在样本中经人工确认出现，不能仅依据均衡抽样假定覆盖。 |
| `error_types`、`notes` | 错误类型用简短字符串数组，如 `跨地点归属`、`漏掉负面维度`、`疑问误作事实`；备注说明不确定性。不要在自由文本中填写密钥。 |

人工可判评论的五个正确性字段和遗漏数都必须明确填写；空值不等于正确，也不等于无法判断。无法判断的评论不进入可判分母，但单独报告数量，以及模型仍作判断的数量。工具把有明确对象/维度、已判断性质与立场、非 `uncertain` 的评论当模型已判：明确评价“整体行程”的证据可以没有 POI 关联。是否已关联地点另外计数。

填写后评分仍需指定相同数据库与任务，重新构建固定样本，防止删除难例、改写模型输出或换任务后缩小分母：

```powershell
uv --directory backend run python ../scripts/p2_review.py score --db ../reports/p2/corpus-20261012T115438Z.sqlite3 --run <分析任务ID> --labels ../reports/p2/review-template/review-labelled.jsonl --output ../reports/p2/review-score
```

生成 `score.json` 与 `score.md`。退出码 0 表示本样本的评论门槛通过；1 表示未通过；2 表示参数、标签结构、基线校验或输出目录错误。已有输出目录不会覆盖。

正确率 = 人工可判且模型已判、对象与主要维度全部正确且没有遗漏的评论数 / 人工可判且模型已判评论数。覆盖率 = 人工可判且模型已判评论数 / 人工可判评论数。按设计目标检查正确率 ≥90%、覆盖率 ≥80%，同时要求 20 篇笔记和 100 条评论完成真实人工审核、三类重点评论范围已确认、无未标注或缺行。分母为 0 时比例为 `null`，不能通过；全部标无法判断、全部机器标注或空模板也不能通过。

报告保留实际分母、弃判、无法判断、未标注、缺行、遗漏及错误类型。笔记形态分布只报告，不自动认证样本代表性。即使 `verdict=pass`，它也只覆盖固定样本的人工评论对象/主要维度门槛，不代表全部 P2 已通过；图片质量、未知目的地探索、服务恢复、费用与 P3 的 20 个歧义地点案例仍需独立验收。没有人类完成标签时，应继续标记语义质量 `not_validated`。
