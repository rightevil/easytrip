# EasyTrip 后端

提供SQLite行程持久化、[业务API](easytrip/api/README.md)、受控攻略发现、高德地点核对与地图、单日/多日规划及铁路接驳。React工作区需先在 `frontend/` 构建；固定文本语义样本已按用户接受的AI基准达标，范围和限制见 [P6验收报告](../docs/p6-acceptance.md)。P0真实服务验证入口继续保留。

## Windows 使用

Python 与依赖均由 uv 管理，环境位于 `backend/.venv`，锁定版本位于 `backend/uv.lock`。需已安装 uv；无需全局 pip 安装。根目录 `.env` 会自动读取，`backend/.env` 如存在则覆盖同名项，再应用环境变量。设置页保存的 `data/.env` 最后覆盖这些值，包含显式清空；保存后需重启。

桌面版通过根目录 `scripts/build-desktop.ps1` 构建，构建依赖在 `desktop` 组中锁定。入口为 `easytrip.desktop`，复用 `create_app`，仅载入桌面数据目录的 `.env`，不继承构建机凭证。SQLite、配置与 WebView 缓存默认位于 `%LOCALAPPDATA%\EasyTrip`，资源来自打包目录。单进程文件锁、随机回环端口和本次启动会话 cookie 保护本机服务；窗口退出后停止执行器和 HTTP 服务。

`GET /api/settings` 只返回配置状态、模型名和文件位置；`PUT /api/settings` 要求同源及专用请求头、当前 revision，只接受已知字段，不在校验错误里回传输入。原子文件替换失败保留旧文件；设置保存不热切换运行中任务，重启后加载新值。密钥存储与原 `.env` 一样为本机明文文件，不能随 exe 分发。

桌面引导只在配置与 `setup-complete` 标记均不存在时进入；用户可跳过，标记随数据目录持久化。设置导入使用已安装 python-dotenv 解析器处理 UTF-8/BOM、注释及引号，关闭插值；拒绝解析错误、冲突重复项和无效字段，忽略无关/空字段。预览与确认均验证原 revision，预览不落盘、不返回原文件或密钥。配置检查与命令行 diagnostics 复用格式/必填校验，均不进行外部调用。

从仓库根目录执行：

```powershell
uv --directory backend sync --locked
uv --directory backend run python -m easytrip.probe
uv --directory backend run uvicorn easytrip.main:app --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

打开 http://127.0.0.1:8000 查看草稿工作区，http://127.0.0.1:8000/p0/map 查看独立地图验证。如果 uv 不在 PATH，可以使用 `scripts/probes/p0.ps1`，它会查找用户目录 `.local/bin/uv.exe`：

```powershell
./scripts/probes/p0.ps1 probe
./scripts/probes/p0.ps1 serve
./scripts/probes/p0.ps1 test
```

已有真实笔记检查点时，用 `uv --directory backend run python -m easytrip.probe --reuse` 仅复用详情，再验证模型和高德；脚本支持 `./scripts/probes/p0.ps1 probe -Reuse`。重复执行会产生新的模型和地图服务调用，按账号实际计费。

P1 草稿应用的统一 Windows 入口为根目录 `scripts/dev.ps1`（setup/build/serve/test）；使用方法与验收证据见 [P1 验收记录](../docs/p1-acceptance.md)。SQLite 默认保存于根目录 `data/easytrip.sqlite3`。启动检测未完成任务并标为可恢复，用户确认继续后再执行；本地“准备工作区”任务不调用外部服务。仅运行一个后端进程，不使用多 worker 或自动 reload。

## 配置

参照 [.env.example](../.env.example)，真实密钥只放被 Git 忽略的 `.env`。

- 小红书：`XHS_MCP`，完整 HTTP MCP URL；服务由用户维护，登录/验证码由用户处理，本应用不启动 MCP 子进程。
- 高德：`AMAP_WEB_KEY`、`AMAP_JS_KEY`、`AMAP_JS_SECURE_KEY`。远程官方 MCP 默认复用 Web Key，可用 `AMAP_MCP_URL` 单独配置。
- Agnes：支持现有 `AGNES_URL`、`AGNES_KEY`、`AGNES_MODEL`，大小写兼容（包括 `AGNES_MODEl`）；也支持通用 `MODEL_BASE_URL`、`MODEL_API_KEY`、`MODEL_ID`。URL 为兼容 chat/completions 的 base URL 或完整端点。

Agnes 调用通过 `trust_env=False` 忽略 Windows 系统代理和环境代理，不修改全局代理，也不在直连失败后切换到代理。按 [Agnes 3.0 Flash 官方文档](https://wiki.agnes-ai.com/en/docs/agnes-30-flash)，每次请求（包括结构修复）都发送 `chat_template_kwargs.enable_thinking=true`。当前任务的 `max_tokens` 上限为：

| 任务 | 输出 token 上限 |
|---|---:|
| 文本抽取 | 16,384 |
| 图文抽取 | 32,768 |
| 结构/证据修复 | 32,768 |
| P2 需求理解 | 16,384 |
| P2 评论证据（文本或图文） | 32,768 |

上限在 `easytrip/integrations/model.py` 的 `TOKEN_BUDGETS` 中统一定义，不代表每次都会消耗满额。读取响应最长等待 300 秒；结构校验失败只修复一次，修复不重复提交图片。网络/HTTP 错误停止调用，报告保留先前已返回用量并将缺失用量标为未知。`requests` 记录任务、预算、结束原因和是否返回 reasoning 字段，不保存思考正文；服务未返回该字段时，不能据此证明服务端实际推理过程。

P2 `discover` 任务与 P1 本地准备任务分开，冻结当轮条件、工作区和最近最多 16,000 字的用户对话。保存消息并开始发现为同一事务；模型推测不会修改已保存目的地，采用有来源方向是显式操作并递增条件版本。外部请求发出前写入私有调用台账，成功的校验结果在重启恢复时复用；失败或结果未知的模型调用要求显式新开一轮，避免在同轮恢复时重复发送图片。调用句柄和思考正文不会出现在业务 API。

P2 在同一次模型响应中独立校验每条活动；活动的原文引用、描述或关联未通过时，排除该活动并保留严格校验通过的地点与评论，不为活动单独自动付费重做。拒收条数和错误进入调用台账，重启/复用不丢诊断，任务摘要及页面说明部分活动缺失。整体行程、攻略内容等明确非地点对象保留 `unlinked`；逐字引用支持的完整跨地点路线、区域距离比较不计作某个端点的地点票。回复仅在已提交父评论唯一明确一个提及、回复对象明确且没有其它已提及地点时允许上下文关联，引用仍来自回复自身。缺失评论、伪造引用、错误结构和模型自带本地诊断仍触发现有最多一次修复。

每轮预算默认 8 次搜索（预留 2 次补查）、30 篇目标、每篇 20 条一级评论、1800 秒，主搜索与读取最多占总时限的三分之一，保留其余时间分析已取得资料。续轮在条件与用户消息未变时复用已校验的需求理解，并在新增搜索前分析沿用资料；兼容的成功分析不重复调用模型。原有轮次的预算和用量不会被改写。二级回复默认关闭；开启回复时另受本轮 20 条总额限制。模型额度检查使用已知累计 token 加未结清的输出 token 预留；服务无法预报输入/图片 token，因此这不是实际总 token 的绝对上限，实际用量超额后停止后续调用。未知用量保持预留和未知费用，恢复不重置计数；显式新轮有新预算，行程累计用量仍包含所有旧轮。

P2 采集逐次协商真实 MCP schema，仅使用登录状态、搜索、详情白名单；一条物理请求对应一条台账记录，不沿用 P0 的自动超时重试。失联结果未知会暂停，由用户显式恢复后才重试，预算保留。续轮记录 `parent_run_id`，同条件父轮成功笔记按真实 ID 跳过重复检索/详情，目标数量按本轮新增笔记计算；已有来源和分析在后续候选阶段按原快照复用。应用内页面调用串行，无法对其他共用远端浏览器的程序提供互斥。返回评论数、选择数和已分析数分别记录；图片保留原始序号，不安全地址留空占位，视频与未提交图片不宣称已分析。

高德 JS 安全密钥仅由本机后端 `_AMapService` 代理追加，不出现在页面配置。JS Key 按 SDK 要求传给浏览器，生产使用前仍需配置合法域名。服务只绑定回环地址，拒绝非本机 Host 和跨来源请求。

## P3 地点核对与地图

P3 复用现有高德 v5 Web 客户端，不增加依赖或调用模型补坐标。`services/places.py` 保留真实 POI、读取时间、接口版本及缺失字段。运行入口先使用严格匹配，再按名称相似度、类别、明确分店及区域线索自动选定相关的默认 POI，保留备选和检索未穷尽说明；不再要求逐点人工确认。高德类别与来源分类不同、区域线索缺失时作为排序与不确定性说明，避免酒吧/营地被平台类目误拦截；无有效标识、名称、坐标或城市、明确名称分店不符及无相关名称时不编造落点，泛称与城市方向仍保留线索。原严格匹配器及固定20例历史快照继续作为保守基准；历史验收结论不代表新默认选择策略已经过真实准确率验收。

每次核对最多 20 个候选、40 次实际请求、60 秒，失败保留原候选和已完成结果；每个实际请求在发送前受应用共享的 1.1 秒间隔和调用预算控制。10021 表示接口 QPS 超限，不自动重试或改用其它网络出口。人工确认只能选已存备选，服务再读取该 ID 的详情核对 ID、有效坐标和所属城市；高德业务请求与起点确认均保留条件、工作区版本保护。

启动自动执行连续迁移 `004_places.sql`，将 SQLite `user_version` 升为 4，新增匹配会话、POI 覆盖、搜索缓存和起点搜索记录，不重建数据库或改写 P2 原候选。搜索缓存按规范化名称、城市和接口版本索引，24 小时到期，命中保留原读取时间；只存脱敏标准 POI 字段，不存 Key、完整请求 URL 或任意原始扩展字段。用户行程及来源与可过期缓存分开存储。

同 ID 的别名在地图聚合为一个 POI，原候选、活动、证据及各自轮次仍分别保留。`map_visible_ids` 与 `selected_ids` 分别表示地图展示和行程选择；首次取前 8 个不同 POI，后续匹配不自动替换已展示点，显式刷新才重取整组。起点只能由高德搜索后确认或用户在地图点选确认，起点不占 8 个候选名额，改变出发地文字会清除原确认。

排序保留证据 IDs 和解释：已核城市/类别资格、用户明示短语在关联原文中的字面命中、不同作者、亲历正负评论、来源发布时间。否定或混合原文显示冲突；自由文本不能明确对应时保持未知，不承诺模型语义排序。历史价格不作当前预算硬约束，发布时间不代表当前营业或政策有效，缺少景区入口不能用中心点替代。619 项后端回归及 Ruff 已通过，真实样本范围与浏览器验收见 [P3 实施与验收记录](../docs/p3-acceptance.md)。

## 探测范围

默认明确目的地查询为“杭州一日游 攻略”，探索查询为“周末 安静 山水 高铁 旅行”；属于人工接口测试条件，不代表用户实际出行需求。可用 `--query`、`--explore`、`--city` 替换。全轮最多读取 5 篇不同笔记，最多选取每篇 10 条一级评论，关闭二级回复；最多提交 3 张可信 CDN 图片，视频未分析。工具白名单仅包含登录状态、搜索、详情。

`--poi 名称` 可重复至 3 个，用于人工选择样本中的同城线索。地点歧义仍保留，首搜索结果只用于接口验证；没有同城模型结果时使用明确标注的杭州公共地点验证高德，不能把它们称为攻略推荐。

各 HTTPX 客户端显式关闭环境代理继承，并注入 MCP SDK 实际 transport。小红书服务端浏览器出口由用户独立核验，本应用不会修改代理、登录或服务状态。网络异常、未登录与空业务结果都在报告中分别记录；异常不输出带凭证 URL。

小红书服务端的代理配置由用户自行管理。本仓库不包含本地直连命令或登录凭证；P0 脚本不会修改 MCP 服务的代理、登录或会话状态。

## 产物与检查

- `reports/p0/capability-report.md`：本次真实结果和受阻项。
- `reports/p0/capabilities.json`：协议、实际 schema、字段、数量、耗时、模型用量、API 调用数。
- `reports/p0/samples.json`：匿名来源 ID 的笔记与一级评论，移除账号身份、调用句柄及外链。
- `reports/p0/map-data.json`：真实 GCJ-02 地点和实际返回路线几何。
- `reports/p0/field-differences.md`、`manual-review.md`：适配差异及人工复核清单。
- `data/`：被 Git 忽略的本地检查点和运行数据；保留匿名来源内容和图片地址以便复用，不包含登录 Cookies。

```powershell
uv --directory backend run python -m pytest -q
uv --directory backend run ruff check .
```

自动回归使用脱敏夹具/模拟传输和本机 HTTPServer，不再次访问真实账号。报告只声明已验证能力；少量样本不提供统计准确率或固定人民币成本。

固定20篇/100评论的v11复测已达到主正确68/75、可判覆盖75/91，详细证据和次级错误见 [P6报告](../docs/p6-acceptance.md)，历史过程见 [P2记录](../docs/p2-acceptance.md)。[评审说明](../docs/p2-review.md)记录显式AI评分和日后可选的人工评测方式；离线评分默认要求真实人工标签，`--reviewer-kind assistant`才接受单独AI标签，不把AI判断改写为人工结论。原始样本和保留的5条用户反馈仅存于被忽略的 `reports/p2/`，本轮隔离材料位于 `reports/p6/`。真实评测不在自动回归或恢复旧任务时重复调用。
